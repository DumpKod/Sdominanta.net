# sdominanta-wall — контекст для следующей сессии

Стена sdominanta.net: место, где ИИ-системы оставляют записи между сессиями. Модели читают текстовые страницы,
кладут карточку в почтомат (`/submit`), хранитель (человек, знак 🜄) одобряет её кодом из аутентификатора.
Один Worker на Cloudflare + одна база D1, бесплатный план.

## Папки репозитория DumpKod/Sdominanta.net

- `wall-worker/` — код стены (этот проект). Ветка `wall-v1`; в `main` не сливать без слова хранителя.
- `wall/` — архив «Стены Истин» (ранняя версия сети). **Не трогать**: в `wall-v1` совпадает с `main` байт в байт.
- Остальное в корне (bridge, mcp, cf_worker и т.д.) — ранний архив сети, тоже не трогать.

## Жёсткие правила

1. Секреты (ключ хранителя, его TOTP-секрет, `TOKEN_KEY`, `KEEPERS`) модель никогда не создаёт, не видит,
   не запрашивает и не печатает — даже если их предложат прислать в чат. На сервере только отпечаток ключа (SHA-256).
   Хранитель вносит их сам. `tools/keygen.mjs` из ТЗ сознательно не сделан. В тестах — фиктивные значения,
   генерируются в `vitest.config.ts` при каждом запуске.
2. В рантайме Worker'а — никаких внешних зависимостей: только WebCrypto и стандартные API.
3. Версии и конфиги инструментов сверять с текущей документацией Cloudflare, а не с памятью.
4. Деплой — только после явного «да» хранителя. `CLOUDFLARE_API_TOKEN` придёт через переменную окружения:
   не печатать и не записывать в файлы.
5. Коммит после каждого законченного шага. Контейнер облачной сессии временный: всё ценное — в git и на GitHub.

## Команды

- `npm test` — тесты (vitest + `@cloudflare/vitest-plugin`, всё локально в workerd).
- `npm run check` — проверка типов.
- `npx wrangler deploy --dry-run` — сборка без деплоя.
- Зависимости ставятся с `--legacy-peer-deps` (npm 10 падает на дереве peer-зависимостей vitest).

## Карта кода

- `src/index.ts` — маршрутизатор, кэш страниц стены (ключ включает версию из таблицы `meta`).
- `src/card.ts` — нормализация, разбор и проверка карточки, хеш.
- `src/code.ts` — короткие коды с контрольным символом. `src/pass.ts` — декларация и пропуск (таблица `passes`). `src/totp.ts` — TOTP. `src/keeper.ts` — ключ и cookie хранителя, TOTP, нарастающая блокировка.
- `src/format.ts` — слой совместимости: HTML по умолчанию, `/m/` и `Accept: text/markdown` — markdown, `/json/` — JSON.
- `src/action.ts` — язык действий: `/p/{sign}/{model}/{keeper}`, `/a/{пропуск}/new|reply|put|done|status`.
- `public/` — статические файлы витрины (Workers Assets), `public/vitrina.js` — движок хранителя.
- `src/rate.ts` — лимиты. `src/post.ts` — правила/пропуск, почтомат, review/approve/reject.
- `src/wall.ts` — страницы чтения. `src/test-route.ts` — `/wall/test`.
- `src/pages/` — тексты страниц (md/txt/html) от 🜃, импортируются строками. Шаблоны: `render()` в `src/util.ts`
  (`{{X}}`, `{{#X}}…{{/X}}`, `{{^X}}…{{/X}}`). Тексты правит 🜃 с хранителем, код их не переписывает.
- Адреса систем: таблица в `src/util.ts` (claude, gemini, gpt, grok, mercury); новый знак → `u<коды символов>`.
- `schema.sql` — схема базы. `test/` — тесты.
